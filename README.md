# cyborg-skills

מאגר ציבורי של Agent Skills מקוריים בעברית, של **The Cyborg**, סוכנות שיווק ממוקאם.
כל סקיל הוא כלי עבודה קטן ועצמאי שרץ בתוך קלוד קוד: קורא הקשר על העסק שלך (מתוך
CLAUDE.md, אם יש כזה), ומחזיר תוצר שיווקי מוכן לשימוש, בלי צורך בידע טכני.

המאגר משרת שתי מטרות. הוא **מגנט לידים**: כל סקיל אפשר להתקין בחינם ולקבל ממנו ערך
מיידי, בלי מחויבות. והוא מיועד לשמש גם **תשתית תוכן** לתוכנית הליווי של הסייבורג:
התכנון הוא שמדף הסקילים בפורטל המשתתפים יישאב ממנו, כך שעדכון סקיל כאן ישתקף בכל
הערוצים ברגע שהחיבור ייבנה (פרטים בהמשך).

## כללי ברזל

- **מקוריות מהיסוד.** כל סקיל נכתב מאפס לפי המתודה המקורית של הסייבורג בלבד, בלי
  להעתיק ובלי להסתמך על שיטה חיצונית או חומר של צד שלישי.
- **בלי IP פנימי.** הריפו ציבורי, בלי חומר פנימי או רגיש של הסייבורג או של לקוחותיו.
- **MIT** לריפו ולכל סקיל בתוכו, ראו [`LICENSE`](LICENSE).
- **read-only / draft-only.** כל סקיל מייצר טיוטות והמלצות בלבד. הוא לא מוחק, לא
  שולח החוצה בפועל, ולא נוגע בקמפיינים חיים.

## איך מתקינים סקיל

לכל סקיל יש `INSTALL.md` משלו עם הסבר מלא בעברית פשוטה, אבל התבנית זהה לכולם.

**שורה אחת (מומלץ), העתק והדבק:**
```
npx degit elad-the-cyborg/cyborg-skills/skills/<category_slug>/<name> ~/.claude/skills/<name>
```
לדוגמה, כדי להתקין את מחולל ההוקים:
```
npx degit elad-the-cyborg/cyborg-skills/skills/02-copy-content/hook-generator ~/.claude/skills/hook-generator
```

**חלופה ידנית:** מורידים את תיקיית הסקיל הבודדת מתוך `skills/<category_slug>/<name>/`
וגוררים אותה אל `~/.claude/skills/` במחשב. בשני המקרים צריך Claude Code מותקן מראש
(VS Code מומלץ).

| 4 | דפי נחיתה ובנייה | בניית דף נחיתה, בניית אפליקציות, בקרת המרות | בתכנון |

וב-[`catalog.json`](catalog.json) (למכונה).

## איך הקטלוג מזין את שאר המערכת

`catalog.json` נבנה אוטומטית מהפרונטמאטר של כל הסקילים על ידי `npm run build`, והוא
כתובת האינטגרציה היחידה של המאגר. התכנון הוא שהוא יזין שני צרכנים: הסאב-דומיין
המגודר `skills.thecyborg.co.il`, שכרטיסי הקטלוג בו נבנים ישירות ממנו בלי תחזוקה
ידנית, ואת מדף הסקילים בפורטל תוכנית הליווי, שקורא אותו דרך ISR ומתעדכן אוטומטית
בכל שינוי. שני החיבורים האלה עוד לא נבנו, זה השלב הבא בתוכנית.

## עבודה על המאגר (למפעיל)

תהליך כתיבת סקיל חדש מתועד במלואו ב-[`AUTHORING.md`](AUTHORING.md): חוזה
הפרונטמאטר, מבנה הגוף הקבוע, וכללי הברזל. בקצרה:

```
npm run new-skill name=... category_slug=... category="..." topic="..." title_he="..." level=... one_liner="..." trigger="..." step1_title="..." example_prompt="..."
```
יוצר תיקיית סקיל חדשה מהתבנית. אחרי כתיבת הגוף:

```
npm run validate   # מוודא שכל סקיל במאגר עומד בתקן
npm run build       # בונה מחדש את catalog.json ו-CATALOG.md, מסרב אם סקיל כלשהו לא תקין
npm test            # מריץ את בדיקות הכלים עצמם (scripts/lib)
```

סקיל חדש נבנה תמיד דרך המפעל, `factory/skill-factory/`, שמרכז את התהליך הזה לכל
בקשה של "תבנה סקיל חדש".
